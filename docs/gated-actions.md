# Gated actions

Forgerie blocks recognised irreversible and external tool calls through shared Durable gate admission. Direct calls enter through `ToolTask.beforeTool`; nested `ctx.executeTool` calls, including codemode and shared child tools, enter through the Durable SDK adapter. The parent and every newly spawned, refreshed or continued Durable child select the hook. The agent receives a blocked result at once and can keep working on other parts. A waiting gate counts toward **Needs your response** and the dock wait. Prompt guidance also covers actions hidden inside scripts.

Optional [risk labels](decision-hints.md#risk-labels) add gateway opinions only after admission. The gateway is never awaited by a gate or tool. An independent memory overlay can add `riskLabel` to a read after approval, refusal, or execution; it makes no Durable transaction and never writes gate state, decisions, execution intent, or tasks. Labels are bounded, can be evicted, and disappear when the last family lease closes or sessiond restarts. Closing one sibling runtime does not clear the family. Live master and risk-label switches suppress stored labels on subsequent reads. Label-only updates do not change Needs your response. A label, including `low`, is not approval or permission to run. Disabled, unconfigured, timed-out, and failed hints leave gate behavior unchanged.

## Default categories

All seven categories are gated by default. `src/shared/autonomyPolicy.ts` owns their schema, labels and defaults. The injectable `AutonomyPolicySource.read(cwd)` returns defaults in this slice. One setting relaxes one category: see [Pushes to the default branch](#pushes-to-the-default-branch). Version 1 already includes `autoPassStops: false`; configurable policy storage comes in slice 4.

| Category | Recognised actions |
| --- | --- |
| `force-push` | Force flags, positive forced refspecs, `--all`/`--branches` and mirror pushes. Unknown repository state, an unknown default branch and implicit destinations gate here, because a configured refspec can force. Explicit refspecs still count with `--tags`; `--repo` names the remote. |
| `push-default` | An unforced push with explicit refspecs to the observed remote default branch, including `HEAD` on that branch. |
| `destroy-local` | Hard reset; clean except preview; checkout/restore of dirty paths, including checkout pathspecs and forced dirty-tree switches; forced or dirty worktree removal; forced deletion of an unmerged branch (`-D`, `--delete --force`, `-d -f`, `-df`). A branch counts as merged when `HEAD` or the fetched default branch of `origin` (`refs/remotes/origin/HEAD`) holds it, so a landed branch can be deleted before local `main` is fast-forwarded; a stale fetch only gates more. Unreadable dirty/merge state gates. Discarding files in a [disposable worktree](#disposable-worktrees) is not gated. |
| `delete-remote` | Push deletion flags or deletion refspecs; GitHub release delete; GitHub API DELETE. |
| `github-merge-close` | `github_write` merge/close; `gh pr merge/close`; issue close unless GitHub confirms `agent-filed`. The issue lookup uses the GitHub client. Lookup failure and pull requests gate. |
| `publish` | npm publish, including `--dry-run`; GitHub release create. |
| `messages` | Tool names ending in `ebay_seller_update`, `ebay_seller_offer_respond` or `ebay_seller_message_reply`, including prefixed MCP names. |

### Pushes to the default branch

**Settings > Plugins > Workflow autonomy > Push to the default branch without asking** lists folders, separated by commas, such as `~/code/sandbox`. A `push-default` call runs without a gate when its repository lies inside one of them. The repository is the main checkout that owns the Git directory (`git rev-parse --git-common-dir`), so a linked worktree anywhere counts as its main checkout's repository, and `git -C <path>` decides by `<path>`, not by the session's folder. Both sides compare by real path, so `~/code` does not match `~/code-work`. The default `none` asks for every push. Relative paths and `/` are ignored. Turning the plugin off asks again.

Only `push-default` is affected. Force-pushes, pushes of all branches, unknown destinations, deletions, publishes and merges still wait for you. An allowed push leaves no gate record; the transcript keeps the command. The cost: a change reaches the shared default branch without you reading it first, and you undo a bad one with a revert. Allow only folders whose default branches are yours.

### Disposable worktrees

Resetting, cleaning, checking out, restoring or force-removing files in a disposable worktree is not gated. A worktree is disposable when its real path is strictly inside `/tmp`, or when it is an active child worktree of this session. A linked worktree directly inside the main checkout's `.worktree/` or `.worktrees/` folder is also disposable, after Forgerie backs up its uncommitted work. Forgerie's own session (`s-<8 hex>`) and child (`c-<64 hex>`) worktrees there are excluded, because they belong to other chats. The backup goes to `<app data>/worktree-backups/<name>-<time>/`: `worktree.json` (path, HEAD, branch), `status.txt`, `tracked.patch` (`git diff --binary HEAD`) and copies of untracked files in `untracked/`. Ignored files are not kept. A failed backup, or untracked files over 200 MB, gates the action. The classifier asks Git for the root of the tree the command changes: the cwd, `cd` or `-C` target for reset, clean, checkout and restore, and the named path for `git worktree remove`. `src/server/sessions/disposableWorktrees.ts` owns the rule. The path is fixed, so a changed `TMPDIR` cannot widen it.

The exemption fails closed in the same cases as the other Git checks. A failed Git read, a Git directory or worktree override, or an uncertain folder (see [Folder tracking](#folder-tracking)) still gates. The prompt guidance tells agents to run the command from the tree, or to name it with `git -C <path>`. A symlink inside `/tmp` counts as its target. Deleting a branch still gates in every tree, because branches belong to the whole repository.

#### Folder tracking

The classifier follows the folder through `cd <literal path>` and reads Git state in the folder where each command runs. The land recipe `cd <worktree> && git commit … && cd <main> && git merge --ff-only … && git worktree remove .worktree/x` therefore reaches the disposable rule for `.worktree/x`. Pushes and merges to shared branches, and destructive commands in the main checkout, still gate.

- **`&&`.** `cd x && rest` runs the rest in `x` or not at all, wherever the `cd` stands in an `&&` chain. A relative path resolves from the last certain folder. `~` expands to the home folder.
- **`;` and newlines.** A `cd` that starts its list also moves the folder for the commands after `;` or a newline. If that `cd` fails, the later command runs in the old folder. The classifier accepts this because its Git read in the missing folder then fails, and the action gates: `cd /does/not/exist; git clean -fd` gates. A `cd` that an earlier `&&` can skip, as in `git fetch && cd x; git clean -fd`, makes the folder after `;` uncertain.
- **Redirects.** `cd x 2>/dev/null &&`, `>/dev/null 2>&1` and `&>/dev/null` are accepted.
- **Uncertain.** These make the folder uncertain for the rest of the script, and every later Git read fails closed: `||` after or before a `cd`; a `cd` in a pipe, a subshell, a `{ }` group, a substitution, a background job (`&`), an `if`/`for`/`while`/`case` body or an unbalanced script; a computed path (`$`, a substitution, a glob, `~user`), an option, `-` or no path; `pushd`, `popd`, `builtin cd`, and a `cd` behind a wrapper such as `env`. `bash -c` inherits the uncertainty.
- **Heredocs and substitutions** run where their command runs. A substitution reads the folder of its command, not a later `cd`. A heredoc body read by a shell uses the folder at the start of its line, and is uncertain when that line has a `cd`.

The cost: one tracking error could run a destructive Git command in a tree the classifier did not check, without a gate. `CDPATH` is not read: if it is set, a relative `cd` can go elsewhere.

The cost: an agent can discard uncommitted work in a child worktree, including the parent resetting a child's tree, without asking. In a project worktree, the backup is the only copy of what was discarded, and backups are not pruned. A clone or worktree that someone keeps under `/tmp` has no protection. Before this rule, these approvals kept workflow runs waiting for up to 6.5 hours, often overnight.

`npm publish --dry-run` stays gated. This avoids relying on npm/plugin/version-specific side effects. Its cost is an approval for a preview. ADR 0003 says `git clean`, broader than the contract's `git clean -f`: interactive and other non-preview clean calls also gate. `git clean -n` and `--dry-run` remain read-only previews.

The quote-aware shell classifier splits command sequences, pipelines, grouping operators and newlines. It removes backslash-newline continuations and inspects `$()` and backticks one level deep, including inside double quotes. Single-quoted text stays data. It recognises shell `-c` one level deep, `cd`, Git `-C`, commands after `if`, `then`, `do` and the other compound-command words, redirects such as `2>&1`, wrapper options for `command`, `exec`, `env`, `nice`, `nohup`, `time` and `sudo`, absolute executable paths, npm global options and Git/GitHub flags in either order. `command -v`/`-V` only look up names and do not execute them. Heredoc bodies are data unless passed to a shell; unquoted heredoc bodies still expand command substitutions. Plain heredoc bodies are data: `cat <<EOF` with the text `git push -f` does not gate. Custom Git directory, worktree, environment or config overrides (including attached `-cname=value`) make state-dependent checks unknown rather than checking the wrong repository. Conditional and grouped cwd changes fail closed, as [Folder tracking](#folder-tracking) describes. A missing remote HEAD never falls back to a local branch name. Ref-less pushes gate as unknown rather than guessing `push.default`, configured remote refspecs or upstream destinations. The cost is approval for some safe feature pushes and complex cwd changes. Unknown state is not permission. The classifier receives read-only Git and issue-label observations. Production Git observations disable optional index locks.

This is recognition, not a shell sandbox. Aliases, computed executable names, functions, indirect commands (including xargs pipelines), nested shells deeper than one level, and shell scripts are not comprehensively inspected. Calls made through codemode `tools.*` are inspected individually, even if the script calculates their arguments. Deploy targets, email tools and paid jobs without one of the recognised tool names are not detected in this slice. An omitted or hidden action can still run. The agent must follow the guidance for these actions.

## Approval, refusal and restart

Approval applies to one saved tool call and its saved arguments. When two or more calls wait and their records were read, the dock shows **Approve all N** after the cards. It sends one approval per call, in order, so each call keeps its own decision, run task and audit entry; a failed approval stays on its card and the rest continue. It does not approve calls that arrive later, and it does not make the user answer sooner. A nested waiting gate resolves to the same blocked text as a direct gate; it does not reject the script promise. A waiting result is not proof that the action ran. The script can keep doing independent work. Deferred/codemode-only tools use a private SDK execution registration for approval, never a new direct model declaration. It admits a background Durable task in the calling conversation. The task uses that conversation's tool registry and environment. Successful tool results retain output, details and diagnostics. Reported tool usage enters the originating conversation's existing `pi.usage` ledger in the result commit. Shared extension tools still use their parent's extension context, as before. A changed conversation cwd or an unavailable tool fails rather than running in a different cwd. Plugin reloads and environment changes are not snapshotted; keep those stable while a gate waits.

The server first commits `approved` and the run task together. The run task then commits an execution-intent checkpoint **before** it invokes the tool. Only that invocation can run it. Restart before intent can run the approved action. Restart after intent records `failed` with **Unknown outcome**, never runs it again, and tells the agent to check the effects. A crash between intent and execution can therefore leave an action that never ran. This is at-most-once execution, not a claim of exactly-once external effects.

Result storage and the placement-tracked result outbox commit together. A live child receives a follow-up. If it has finished or is missing before admission, the parent receives it. Queued delivery is not counted as placement. Withdrawn unplaced inputs retry with fresh receipts and select a live recipient again. Already placed inputs do not repeat. Refusal never runs the tool and delivers `The user refused gate <id>: <description>.` Approval and refusal each record one `gated` decision by `user`, inside the same commit as admission/refusal.

Gate identity uses the Durable conversation and tool-task IDs, not the model's call ID. Nested gates also use an invocation-local ordinal; different nested calls and repeated model call IDs cannot share an approval. The SDK adapter keeps the calling conversation and task context until the source call finishes, then removes it. Calls without a live Durable invocation fail closed. Replay after gate admission reuses the gate and its transcript entry. A new call needs a new approval.

## HTTP API and wire schemas

Browser requests add `/api` (and, for machine routing, `/machines/:machine`). Sessiond uses the paths below. The existing session wildcard proxy forwards these paths and errors unchanged. `cwd` identifies the parent session, not a child worktree.

| Method and path | Request | Response |
| --- | --- | --- |
| `GET /sessions/:id/gated-actions` | Only query `cwd`. | `GatedAction[]`, newest first. Non-Durable sessions return `[]`. |
| `POST /sessions/:id/gated-actions/:gid/approve` | Exactly `{cwd}`. | `GatedAction` with `state.kind: "approved"`. Execution and delivery continue in the background; refetch on `workflow_runs_changed`. |
| `POST /sessions/:id/gated-actions/:gid/refuse` | Exactly `{cwd}`. | `GatedAction` with `state.kind: "refused"`. |

Invalid input returns 400, missing gate/session 404, and a non-waiting gate 409. Errors have shape `{error: string}`. Admission and terminal record changes emit `workflow_runs_changed`. Waiting gates add to `waitingOnYou`, separate from non-blocking flagged decisions.

`src/shared/gatedActions.ts` exports `GatedAction`, `GatedActionState`, `GatedActionEntry`, and their TypeBox schemas. `GatedAction` is `{id, conversationId, by, tool, args, category, description, requestedAt, state}`. `by` is `parent` or `child <name>` (conversation ID fallback). State is `{kind: "waiting"|"approved"|"refused"}` or `{kind: "ran", result, at}` or `{kind: "failed", error, at}`. `result` is the JSON tool result, not just text. Times are Unix milliseconds. The Durable document kind is `forgerie.gated-actions`.

Transcript kind `forgerie.gated-action` has `{id, by, tool, category, description, command}`. `command` is a preview limited to 4000 characters. Obvious URL credentials, password/token flags, Authorization headers and sensitive JSON field names are redacted in this preview only. The saved `args` stay exact and are not truncated. This is best-effort display redaction, not secret storage: the gate API, tool output and result delivery can still contain secrets. The entry is for the reader, not extra model input. `src/shared/autonomyPolicy.ts` exports `GatedCategory`, `AutonomyPolicy`, and `AutonomyPolicySource`.

## Verification

`gatedActions.test.ts` covers more than 40 gated and allowed commands, state observations, wrappers, flag order, previews and heredocs. `disposableWorktrees.test.ts` runs real Git against a scratch clone, a child worktree, the project and a symlink into it. `durableGatedActions.test.ts` runs real Durable journals: parent and child hooks, replay admission, approval/refusal, live-child versus parent delivery, policy injection, ordering, and crashes before/after execution intent and after an effect. `gatedNestedActions.test.ts` runs real codemode scripts for force-push, deferred eBay tools and allowed commands. It checks script continuation, child attribution, exact-once approval, refusal and restart. `gatedActionRoutes.test.ts` calls the production service through Fastify and runs a real push to a scratch bare remote. Proxy tests cover unchanged requests and 409 errors.

`GATED_ACTIONS_REAL=1 ./scripts/gated-actions-real.ts` uses a real model in a temporary profile. It asks for a force-push to a scratch bare remote with a divergent tip. The call must block. The agent must write an independent progress file before HTTP approval. A pre-push hook counts exactly one invocation; the script also checks the remote commit and the agent's result report. It removes copied credentials and scratch files on exit. Add `GATED_ACTIONS_NESTED=1` to run the force-push and independent step inside one codemode script; it checks the same gate and once-only execution path. Model calls incur costs. SIGKILL cannot run cleanup: remove `/tmp/forgerie-gated-actions-real-*/agent/models.json` after an interrupted check.
