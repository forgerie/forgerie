Keep a table a table until it truly does not fit, and read a record as a record when it does not.

A table was stacked into records whenever its natural width missed the reading
column. Natural width asks whether every cell can hold its sentence on one
line, and a cell holding a sentence never can, so every two-column table of
prose stacked at every posture — the reader lost the table to save a line
break. Each column is now charged what it needs rather than what it wants: a
short column costs its content, and a column of prose may wrap down to 224px.
The three-outcome table that started this renders as two wrapping columns at
704px and 932px, where it used to be three labelled records.

A stacked table is no longer one field per line. The record grid gains and
loses field tracks from the room a record has and the width its own values
asked for, so six short fields pair up where two sentences take a row each.
Six columns of dates and names cost 506px on a folded phone against 770px
before, and the record still reads as one block instead of eleven alternating
lines.

A two-column table now writes both headings once above the records instead of
repeating the second one under every title. That repetition was the thing that
made a stacked table something to skip: the same three words, once per row,
saying nothing after the first. The value that loses its label takes the whole
row and is drawn quieter than the name it belongs to.
